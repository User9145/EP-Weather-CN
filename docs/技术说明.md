# EP「资讯与兴趣」本地版 · 完整技术说明

**版本**：v1.0（安装包迭代 v12）
**平台**：Windows 11（21H2 – 25H2），依赖 ExplorerPatcher 与 WebView2 Runtime
**技术栈**：C# (.NET Framework 4.0，纯 BCL + P/Invoke，无第三方依赖)、静态 HTML/CSS/JS、批处理安装脚本

---

## 1. 项目概述

Windows 11 取消了任务栏的「资讯和兴趣」（News and Interests）组件。ExplorerPatcher（EP）虽然能在 Win11 上还原 Win10 任务栏并重新启用该组件，但其天气面板指向的是线上服务（Google/MSN），在国内网络环境下基本不可用，且无法自定义。

本项目在 EP 的机制之上做了一个**本地渲染**的替代实现：保留 EP 的任务栏入口（温度 + 图标 + 点击弹窗），但弹窗页面不再是 EP 写死的线上地址，而是本地生成器实时抓取数据（天气/新闻/行情）、渲染出的静态页面 `w.html`，由本机一个小服务驱动热更新。

设计目标按优先级排列：

1. **稳定优先**：纯色不透明界面，不依赖 DWM 亚克力/Mica（已知在部分 NVIDIA 显卡上因 MPO 无法上屏）。
2. **零侵入性运行**：不注入 explorer、不装驱动、不常驻大进程。
3. **EP 升级免疫**：EP 更新后安装包可自愈，DLL 补丁对 EP 版本不敏感。
4. **无窗口后台运行**：所有常驻组件均为 winexe 子系统，不开机弹控制台窗口。

```
用户点击任务栏天气按钮

        ▼

               │                      │   → file:///C:/PROGRA~1/
               │                      │     EXPLOR~1/EPWLOC~1/w.html

        │  w.html (本地)  │◄────────────┘

        └──────┬───────┘
               │ fetch() 火-and-忘 (页面无法直接开外部链接)
               ▼
   ┌────────────────────────────┐
   │ ep_cmd_server.exe (winexe)  │  127.0.0.1:24381
   │  ├─ /open      外部浏览器开链接 │
   │  ├─ /setloc    改城市→重生成    │
   │  ├─ /refresh   全量重生成      │
   │  ├─ /vis(wait) 弹窗显隐长轮询   │
   │  ├─ /newshtml  新闻热更新片段   │
   │  └─ /newswait  新闻就绪唤醒    │
   └──────┬─────────────────────┘
          │ 定时调度 + 窗口外壳自愈 (1s 轮询)
          ▼
```

**运行时进程全集**（总共三个）：

| 进程 | 说明 |
|---|---|
| `dllhost.exe` | EP 的天气宿主 COM 服务器（EP 自带机制），承载 WebView2 |
| `ep_cmd_server.exe` | 常驻命令通道 + 调度器 + 窗口外壳守护，实测 ~10 MB 内存 |
| `ep_weather_local.exe` | 一次性页面生成器，由服务端/计划任务唤起，跑完即退 |

## 3. 组件清单

### 3.1 `ep_weather_host.dll`（二进制补丁对象，EP 官方文件）

EP 的天气面板宿主，注册为 COM Local Server，由系统 dllhost 托管。它创建一个带 WebView2 的弹窗窗口并导航到一个写死的天气 URL。

本组件对它做**两处二进制补丁**（详见 §5.1）：
1. 把宽字符 URL 槽里的 Google 导航地址改写成本地 `file:///` 地址；
2. 把 WebView2 视口高度常量 600 改为 1200（原值按页面 CSS 像素定高，物理高分辨率屏上只有半屏）。

补丁在内存中原地完成（等长改写，多余字节补零），不改变 DLL 结构与签名之外的任何字节。

### 3.2 `w.html` —— 协议钩子页面

由生成器产出的静态页面，身兼三职：

**① 视觉本体**：Win10 资讯与兴趣的复刻 UI——两列卡片流、蓝色天气卡、市场卡、图文卡片，深色系实心配色（页面 `#424243` 底、卡片 `#2e2e33`），纯 CSS 实现上浮动画与噪点纹理。

**② EP 数据协议钩子**（关键 trick）：EP 的任务栏按钮不是画死的，它依赖弹窗 DOM 里的特定钩子来抓取温度/图标/位置文本。页面按 EP 原版页面的 DOM 约定埋入同名节点：

| 钩子 | 用途 |
|---|---|
| `wob_tm` / `wob_ttm` | 当前温度（°C/°F），驱动任务栏温度文本 |
| `wob_loc` | 城市名，驱动任务栏 tooltip |
| `wob-unit` / `wob_t` | 温度单位与体感 |
| `.ULSxyf` 容器 `offsetHeight` | EP 按 `offsetHeight × 353/367` 反推弹窗窗口高度——页面用真实内容高度控制弹窗尺寸 |
| `YQ4gaf zr758c img + alt` | 天气图标 + 描述，驱动任务栏图标 |
| 隐藏的 `wob_dts` / `YfftMc` | 供 EP 的抓取脚本读取的隐藏字段 |

**③ 本地命令客户端**：页面内 JS 通过 `fetch('http://127.0.0.1:24381/...')` 火-and-忘调用本地服务——因为 EP 的 WebView2 弹窗内直接 `window.open` 外链会破坏弹窗状态，所以"在浏览器新窗口打开"这个动作外包给了本地服务代劳。

### 3.3 `ep_weather_local.exe` —— 页面生成器（winexe）

一次性进程（无参 = 全量生成；`--weather` 只刷新天气；`--news` 只刷新新闻）。纯 C# 字符串模板拼出 `w.html` 与 `news.html`。数据来源：

| 内容 | 来源 | 说明 |
|---|---|---|
| 天气 | Open-Meteo API（`api.open-meteo.com`） | 城市名先地理编码成经纬度，拉 7 天预报；免密钥 |
| 市场 | 腾讯行情（`qt.gtimg.cn`） | 指数/个股快照 |
| 新闻 | RSS（中新网滚动新闻等） | 解析后生成两列卡片 |

生成逻辑：

- 读取注册表 `HKCU\Software\ExplorerPatcher` 的城市、单位等设置；
- 天气渲染进蓝色天气卡的同时写入 EP 协议钩子节点（`wob_tm`/`wob_loc`/图标 `alt` 等），任务栏温度/图标/tooltip 因此同步更新；
- 卡片用贪心高度平衡算法（左右列累计高度比较）分配，接近 EP 原版的错落两列；
- 页面单文件自足，写盘用临时文件+原子替换（`WriteAtomic`），避免 WebView2 读到半个文件。

生成器支持多语言模板（中/英由注册表区域决定）。

### 3.4 `ep_cmd_server.exe` —— 本地命令通道 + 调度器 + 窗口守护（winexe）

单文件、无配置、纯 `TcpListener` 实现（不用 `HttpListener`，因此**不需要管理员、不需要 URLACL**）。三条常驻线程：

**① KeepaliveLoop（60s 周期）**：COM 保活 + 内容调度（详见 §5.5、§5.6）。

**② FlyoutFxLoop（25ms 轮询）**：弹窗显隐跟踪 + 窗口外壳自愈（详见 §5.3、§5.4）。

**③ 主 accept 循环**：每个请求一个线程池任务。

HTTP 端点：

| 端点 | 行为 |
|---|---|
| `GET /open?u=<url>` | 按注册表 UserChoice 找到默认浏览器 exe，带 `--new-window`/`-new-window` 打开链接 |
| `GET /setloc?loc=<城市>` | 写注册表 → 全量重生成 → 通知面板刷新 |
| `GET /refresh` | 全量重生成 + 通知面板 |
| `GET /setint?sec=N` | 改新闻刷新间隔（注册表 `WeatherContentUpdateMode`） |
| `GET /vis` / `/viswait` | 弹窗显隐状态；`/viswait` 为长轮询（≤15s），显隐变化即刻唤醒页面 |
| `GET /newshtml` | 返回新闻片段（左右列，`<!--SPLIT-->` 分隔） |
| `GET /newswait` | 长轮询，新闻重生成时唤醒页面做无刷新热替换 |

进程单实例（命名互斥体 `Local\EPNewsCmdServer`），开机经 Run 键自启，winexe 无窗口。

### 3.5 `ep_patch_dll.exe` —— DLL 补丁工具

对官方 `ep_weather_host.dll` 做等长二进制改写（§5.1），并提供状态机检查供安装脚本做自愈决策：

```
exit 0 = 已打预期 URL 的补丁
exit 2 = 官方原 DLL，可补丁
exit 3 = 损坏 / 不支持
exit 4 = 被其它路径的旧补丁打过，需先还原
```

### 3.6 `GuiStrings.exe` —— Win32 资源字符串改写工具

通过 `LoadLibraryEx(LOAD_LIBRARY_AS_DATAFILE)` + 资源枚举解析 `RT_STRING` 块，把 EP 设置界面里的「Weather」字样改写为「News and Interests」（只改 zh-CN/中性语言块）。可选步骤，失败不影响主功能。

### 3.7 `install.bat` / `uninstall.bat` —— 安装脚本

安装流程（需管理员）：

1. **环境检查**：管理员权限、EP 是否已装（注册表键或 `C:\Windows\dxgi.dll`）、WebView2 Runtime（缺失则自动下载静默安装）。
2. **安装目录决策**：首选 `C:\Program Files\ExplorerPatcher\ep_weather_local`。因补丁后的 URL 槽只有约 50 个宽字符，必须全程用 8.3 短路径——脚本自动查询三段短名，缺失时 `fsutil file setShortName` 补齐；整卷禁用 8.3 名时 `fsutil 8dot3name set C: 0` 再补；都不行才回退 `C:\EPW`。
3. **DLL 自愈与补丁**：按状态机决策——已打好跳过；官方则先备份 `.orig`；损坏/异源补丁则从 `.orig` 或包内 `official\` 副本（版本号比对）还原后再打；补丁前杀掉占用 DLL 的 dllhost。
4. **文件部署**：组件拷入安装目录、`icacls` 授当前用户完全权限（页面刷新需要写 w.html）。
5. **自启与计划任务**：Run 键注册两个进程 + 每小时 `--weather` 的计划任务。
6. **收尾**：生成页面（无产出则用包内 `fallback_w.html` 兜底）→ 起本地服务 → 重启 explorer。

## 4. 配置与数据流

**注册表（`HKCU\Software\ExplorerPatcher`）**：

| 值 | 含义 |
|---|---|
| `WeatherLocation` | 城市名（⋯ 菜单里可改） |
| `WeatherContentUpdateMode` | 新闻刷新间隔（秒），页面已不暴露设置入口，固定走默认值 |
| `WeatherWindowCornerPreference` = 1 | 圆角偏好（脚本写入，配合正方形窗口角） |

**任务栏天气**：由生成器从 Open-Meteo 拉取并写进页面钩子节点，EP 显示弹窗时读取 DOM 同步任务栏。小时级网格刷新（服务端 60 分钟调度 + 计划任务双保险）；改城市后服务端立即重生成并 `PostMessage(WM_FETCH_DATA)` 通知 EP 即时重读。

**新闻热更新**：服务端按间隔重生成 `news.html` → 递增代际计数 → `/newswait` 长轮询即刻唤醒页面 → 页面拉 `/newshtml` 原地替换两列内容。页面自身没有任何定时器，唤醒完全服务端驱动，空闲零 CPU。

**日志**：`%APPDATA%\ExplorerPatcher\ep_cmd_server.log`，256 KB 封顶（超限只保留最近 128 KB）。

## 5. 核心技术难点与解法

### 5.1 DLL 补丁：版本无关的 URL 槽定位

EP 各版本写死的天气 URL 不同（`https://www.google.com/search?hl=%s&q=weather%s%s` 等），不能硬编码偏移。补丁工具采用两级定位：

1. **精确匹配**：先找已知 URL 的字节序列；
2. **泛化扫描**：枚举镜像中所有 UTF-16LE 编码的 `http(s)` 可打印 URL，按关键词（weather/forecast/google/msn/bing）过滤，排序偏好含 "search" 且最长者，要求长度 ≥ 新 URL 且全镜像唯一（拒绝打不唯一的补丁）。

改写等长，多余字节置零（原槽自带 NUL 填充）。这样 EP 升级换了 URL 串也能大概率自动适配。

高度补丁是机器码级定位：`B9 58 02 00 00`（`mov ecx,600`）。为避免误伤其他 `mov ecx,600` 站点，要求候选点 ±400 字节邻域内同时存在 EP 布局常数 181 / 152 / 1333；若全镜像只有唯一站点则直接采用。

### 5.2 为什么不用 HttpListener / 为什么端口命令通道

WebView2 弹窗内 `window.open` 外链会让 EP 认为弹窗状态异常。原始思路是 hook 页面点击，但最省事且零注入的做法是页面把命令发给本机回环端口，由一个有正常窗口站位的进程代为打开浏览器。`TcpListener` 直接读请求行手写 HTTP 响应，无需 netsh URLACL、无需管理员，且天然只允许本机访问（`IPAddress.Loopback` 绑定）。

### 5.3 窗口外壳手术：标题栏的剥除与窗口回收

EP 以 `WS_OVERLAPPED | WS_CAPTION` 创建弹窗，并按**含标题栏**的样式 `AdjustWindowRect` 计算尺寸、把窗口**外框底边**贴到任务栏顶。直接的结果是客户区下方悬空一个标题栏高度。

进一步地，EP 在每次 explorer 重启、每次弹窗重停靠后都会以"含标题栏"的样式重新 `SetWindowPos`——只剥样式（旧实现）会在窗口外侧留下一圈比客户区大的黑框（窗口类背景刷是 `BLACK_BRUSH`）。

当前实现的三步自愈（每秒检查，EP 把样式改回来就再剥一次）：

1. **剥皮前测量**：先取 `GetWindowRect` + `GetClientRect`，记下客户区本该有的 `cw×ch`；
2. **剥样式**：清 `WS_CAPTION`，`DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE = DONOTROUND)`，先 `SWP_FRAMECHANGED` 重算非客户区；
3. **回收窗口**：再次 `SetWindowPos` 把外框收缩回 `cw×ch`，**右下两角钉死**（正是 EP 停靠所依赖的两条边）——客户区之上不再有多余的窗口区域，黑框消除。EP 每次显示时会重新停靠计算，即使出现瞬态也会在下一次点击时自我纠正。

另外两个保险：

- **`KillBackdrop`**：每秒把 `DWMWA_SYSTEMBACKDROP_TYPE` 钉为 `DWMSBT_NONE`，防 EP 自带的 Mica 在某些环境渲染成纯黑（页面本身不透明，这是纯防御措施，开销可忽略）。
- **`FixWebViewStretch`**：只在窗口**隐藏时**把 WebView2 子窗口链（`Chrome_WidgetWin_*` / `Chrome_RenderWidgetHostHWND`）拉伸覆盖整个客户区——可见时改 WebView2 子窗口尺寸会让其合成器卡死白屏，隐藏时则安全，且能在下次显示前盖住剥皮留下的条带。

跨进程 `SetWindowPos` 移动窗口**会被 EP 拒绝**（实测返回 TRUE 但位置不变，EP 内部强制重停靠），所以位置类修正全部只能借 EP 自己的重停靠时机完成——这是动画改为页面内 CSS transform 实现的根本原因。

### 5.4 显隐同步：长轮询 + 去抖

弹窗显隐由服务端 25ms 轮询 `IsWindowVisible` 跟踪，页面通过 `/viswait` 长轮询订阅：隐藏时页面用 CSS `translateY(105%)` 收起面板（显示弹窗时由窗口出现本身提供"弹出"观感，显示时页面播 0.3s 上滑动画，Win10 手感）。

**踩过的坑**：EP 打开弹窗的序列里会连续多次交错显示/隐藏窗口（停靠重算），若页面收到一次"隐藏"就立刻收起，最后一次瞬时隐藏会留错状态——窗口明明显示着，面板却收着（整块灰色），必须点一下触发兜底才恢复。解法是对隐藏信号做 **600ms 去抖**：收到隐藏后延迟收起，届时再拉一次 `/vis` 复核，仍隐藏才收起；显示信号依旧即时。

### 5.5 COM 保活：为什么任务栏按钮会"消失"

EP 天气宿主是 COM Local Server（dllhost 托管）。COM 有闲置卸载机制：弹窗久不打开，dllhost 被回收，任务栏上的天气按钮随之消失。服务端的 keepalive 线程持续持有一个 `IEPWeather` 接口引用（`CoCreateInstance` 后不释放，进程存活期内永不归零），`epw_OutstandingObjects > 0` 使 `DllCanUnloadNow` 永远返回 `S_FALSE`，dllhost 永不被闲置卸载。窗口句柄变化（explorer 重启重建）时释放旧代理、重打新引用。

### 5.6 内存与功耗控制

- 服务端无任何内容缓存（新闻每次现读文件），无堆积面；
- 两个常驻/半常驻 exe 均附 `gcConcurrent` 配置；
- 服务端每 5 分钟 `SetProcessWorkingSetSize(-1,-1)` 修剪工作集（空闲进程把页面还给 OS，需要时瞬时 faults 回来），实测常驻 ~10 MB；
- 页面零定时器：新闻唤醒靠服务端长轮询推送，空闲时全链路零 CPU；
- winexe 子系统：进程无控制台窗口，开机自启不再弹黑窗。

### 5.7 透明效果的放弃（技术决策记录）

曾实现过完整的亚克力/Mica 版本（含背光叠层、截图快照循环、DWM 材料控制，约 200 行），最终**整体拆除**，原因：

- **NVIDIA MPO（Multi-Plane Overlay）**：在 RTX 50 系等显卡上，DWM 合成走的覆盖平面会让亚克力/Mica 的实际输出到不了物理屏幕——截图正常、肉眼灰黑，属驱动层行为，应用侧无解；
- 截图快照循环等绕行方案复杂且脆；
- v1.0 定调实心深色（页面底 `#424243`、卡片 `#2e2e33`），视觉损失小、稳定性收益大。

## 6. 兼容性说明

| 维度 | 说明 |
|---|---|
| OS | Win11 21H2–25H2（EP 启用 Win10 任务栏的任意版本）；Win10 亦可 |
| EP 版本 | 补丁对 URL 泛化匹配，EP 升级 weather URL 变化大概率自动适配；DLL 状态机损坏时可从 `.orig` 或包内官方副本自愈 |
| 安装路径 | 首选 `C:\Program Files\ExplorerPatcher\ep_weather_local`；8.3 短名被禁用的系统自动 `fsutil` 开启补齐，仍失败回退 `C:\EPW` |
| 前置依赖 | EP 本体、WebView2 Runtime（安装脚本自动补装） |
| 硬件坑 | NVIDIA MPO 下不可恢复透明效果（故实心设计）；其余无硬件依赖 |
| 卸载 | `uninstall.bat` 还原官方 DLL（`.orig`）、删计划任务/自启/文件 |

## 7. 已知限制

1. EP 打开弹窗瞬间的显隐抖动仍会发生（服务端日志可见 1/0 交替），去抖已覆盖其对页面的影响，但 `/viswait` 会因此多醒几次，无害。
2. 新闻来源为抓取生成，源站改版时需要更新生成器模板。
3. WebView2 自身内存（dllhost 内）不归属本组件管理。
4. 面板圆角固定为直角（Win10 风格），跟随 `WeatherWindowCornerPreference`。

## 8. 构建

```bat
rem 需要 .NET Framework 4.0 SDK 的 csc（系统自带于 C:\Windows\Microsoft.NET\Framework64\v4.0.30319）
csc /nologo /target:winexe /out:ep_cmd_server.exe EpCmdServer.cs
csc /nologo /target:winexe /out:ep_weather_local.exe WeatherGen.cs
csc /nologo /out:ep_patch_dll.exe PatchDll.cs        :: 控制台工具，保留输出
csc /nologo /out:GuiStrings.exe GuiStrings.cs        :: 控制台工具，保留输出
```

部署到本机：编译后运行 `deploy20.bat`（杀旧服务 → 拷新 exe → 重启服务 → `/refresh` 热更新页面，无需重启 explorer）。

打包发布：更新 `release\EP_Weather_Local_v1.0\` 下的 exe/config/页面后压缩为 `EP_Weather_Local_v1.0_vNN.zip`；包内版本号恒为 v1.0，迭代号只在文件名上体现。
